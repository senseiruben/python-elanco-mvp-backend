# Tick sightings MVP API by Ruben Ward

## Project Overview
This is my Minimum Viable Product REST API made to ingest, validate and transform the provided tick sighting data. It provides multiple endpoints with search and filtering options as well as a few analytical reports.

This project was built with python, pandas and fastapi, for an easy api with strong data validation.

## Key features
- Data ingestion: Automatically reads, validates and transforms the 'xlsx' file.
- Search and filters: Filter sightings by, location, date, or a date range.
- Analytics: Get sightings counts based on location as well as the trends going over many months.

## Project Stack choices

Python -> I chose python as it was the language I am most familiar with for data processing, I didn't want to overcomplicate the project, I am already familiar with a few of the libraries that I would be using
so it made python an easy pick.

Pandas -> I am using pandas for data ingestion and querying. This seemed like a pretty obvious option as it is industry standard and I am already familiar with it and research showed me it is efficient for data consumption/ingestion. Alternatives existed for big datasets, but as there is a time constraint I wanted to avoid the unnecessary complexity. I am also using this for storing my data as well as queries, I considered SQLite and SQLAlchemy, but it seemed overkill to learn these tools and would extend the project unnecessarily when I can use In-memory storage. 

FastAPI -> Having researched into different frameworks, Django REST seemed like a good option, it scales well for large projects and is well known, but it seemed unnecessary for a small MVP and also seemed like it would take up extra time. Flask is also small, lightweight and easy to learn, but my research showed FastAPI was more suited to my needs, it has good performance and I can use FastAPIs built in Pydantic integration for automatic data validation. FastAPIs built in Swagger UI for doc generation was also a huge upside, this reduced development time considerably and made testing really simple.

Docker -> Used to ensure the project is easily run and solve the, "it works on my machine" problem in case it is encountered.

Uvicorn -> FastAPI is built on ASGI (asynchronous server gateway interface) and Uvicorn is the industry standard for ASGI servers running fastAPI. Uvicorn is high-performance and incredibly simple to use, other ASGI servers, such as hypercorn, required more setup and were over-complex for this task.

## Run Instructions
Requirements:
Python 3.11.9
Git
Docker (Optional method)

Run the following commands in command prompt:
```
git clone https://github.com/senseiruben/python-elanco-mvp-backend.git

cd python-elanco-mvp-backend

```

Option 1: Run locally
```
pip install -r requirements.txt

python -m uvicorn main:app
```


Option 2 Docker:
```
docker build -t ruben-backend .

docker run -p 8000:8000 ruben-backend
```

Then head to http://127.0.0.1:8000/docs for the docs automatically generated by Swagger UI

## Basic how to use

Easiest way to view and use this is to use FastAPIs built in Swagger UI

Step 1: go to http://127.0.0.1:8000/docs
Step 2: Click on an endpoint, eg: region counts
Step 3: Click try it, then execute
